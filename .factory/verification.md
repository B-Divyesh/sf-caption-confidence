**Work order:** `caption-confidence-verify-1`  
**Candidate:** `3525f2c9174e32d9e27a5d7f507b3ba5dd3ca2a5` (`main`)

**Scope:** independent clean-checkout QA; product source was not modified.

## Verdict

**FAIL.** The candidate builds and its unpacked extension works locally, but the live product cannot be downloaded: its only extension ZIP link returns HTTP 404. The live site also produces a console/page error on every load because it registers a service worker that is absent from the production build/deployment. These violate the end-to-end delivery and no-console-errors acceptance gates.

## Defects

### P1 — Blocker: deployed extension download is 404

**Reproduction:** visit the live home and activate **Download extension ZIP**, or request `https://caption-confidence.sociobot.in/downloads/caption-confidence-chrome.zip`.

**Actual:** HTTP 404 Azure Static Web Apps error page.

**Expected:** the 16,197-byte ZIP from the candidate build downloads and can be unpacked/loaded in Chromium.

**Impact:** a new user cannot obtain the browser extension, so the real job-to-be-done is unavailable live. Although the source page assets match the candidate, the deployment does not contain this required build artifact.

### P1 — Blocker: production service-worker registration always fails

**Reproduction:** load the live home in a clean HTTPS Chromium context and inspect console/page errors; request `/sw.js`.

**Actual:** `/sw.js` is HTTP 404; registration throws a page error on every load. `dist/site` has no `sw.js` even though the source contains `site/sw.js`.

**Expected:** either ship `/sw.js` with the build (and validate update/offline behavior) or do not register it. No console/page errors on load are permitted.

**Impact:** breaks the promised offline/cache path and fails the quality gate.

### P2 — Settings do not update the current caption

**Reproduction:** import a VTT whose first cue is active, change word pairs from `ship / sip` to `vine / wine`, or toggle **Show enhanced captions**, while that cue remains active.

**Actual:** the active overlay retains old markup/visibility. It updates only after playback crosses to another cue. In the tested case, disabling the overlay left `display: block` until the cue changed; changing pairs left `<mark>ship</mark>` in place until a different cue rendered.

**Expected:** a setting change immediately redraws/hides the current overlay and gives immediate feedback.

**Impact:** core attention and visibility controls are misleading during the exact line the user needs to catch.

### P3 — Missing site content/framing policy headers

**Actual:** live 200 responses do not include CSP or `X-Frame-Options`/`frame-ancestors`.

**Expected:** a static-site CSP appropriate to the self-hosted assets and an explicit frame-ancestors policy.

## Required release disposition

Do not release this candidate as PASS. Redeploy `dist/site` including `/downloads/caption-confidence-chrome.zip`; ensure the service worker is actually emitted or remove its registration; fix the active-cue redraw behavior; then rerun live download, service-worker/offline, console, and core extension regression checks.
